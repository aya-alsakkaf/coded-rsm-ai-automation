Lesson 2 · the idea

A calendar reminder that also does the work.

The idea
SCHEDULED TASK

A scheduled task is a saved prompt that Claude runs on a frequency: hourly, daily, weekdays, weekly or manual. Its prompt calls your skill and reads through your connectors.

A reminder that only reminds you…
…versus one that does the work and leaves the file.

Click Scheduled in the left sidebar, then New task.

Lesson 2 · what it can do

It runs in the cloud. Each run starts fresh.

The idea
HOW A SCHEDULED RUN WORKS

The task runs even when your laptop is closed. Each run is its own session. Do not rely on it to recall the last run: the prompt, the skill and the folders must say everything.

A new joiner on each run…
…who only knows the prompt, the skill and the folders.

Anything the run needs must be written down.

Lesson 2 · step by step

Six steps to a schedule.

  • Open: click Scheduled in the left sidebar.
  • New task: upper right, then Set up manually.
  • Name and prompt: the prompt calls your skill and names the folders.
  • Approval mode: choose the mode that lets the run save and move files without waiting for you.
  • Frequency: daily at 08:00. Kuwait works Sunday to Thursday, so Friday and Saturday runs log No new files.
  • Test: run it once on demand and check the output.

If the test run works, the schedule will work.

Lesson 3 · inputs and outputs

Inbox, Processed, Outputs.

The idea
CHANGING INPUTS AND DELIVERED OUTPUT

The run reads new files in the Inbox and moves each one to Processed. It saves a file with the date and time in its name to Outputs, or an email draft.

An in-tray and an out-tray…
…nothing is read twice, nothing is overwritten.

Name outputs client-task-date-time.

Lesson 3 · the empty folder

No files? One honest line.

The idea
THE EMPTY-FOLDER RULE

If the Inbox has no new files, the run writes No new files in the run log and stops. It never reprocesses old files to fill the gap.

An automation that breaks on an empty folder…
…is not an automation.

Read the run log every morning, even on quiet days.

Lesson 4 · rules

The rules are yours, not Claude's.

The idea
DEPARTMENT RULES

Thresholds, sign-off levels, file names and what never happens (no adjustments, no conversions). Written in the skill word for word, so every run follows them.

The firm's review rules…
…copied into the skill, not paraphrased.

A paraphrase is a new rule.

Quick check

Lesson 4 · review

Drafts only. A named person signs off.

The idea
REVIEW STEP AND RUN LOG

Every output is marked DRAFT and ends with Reviewed by. Each run saves a run-log file in the Log folder: date, files read, items flagged, file saved.

A working paper with a reviewer's initials…
…a file with DRAFT and Reviewed by.

The agent routes. The supervisor decides.

Lesson 5 · when a step fails

When a step fails, the run says so.

  • Test it: copy mirqab-locked-test-file.pdf, a file no run can read, into the Inbox. Run on demand.
  • Good run: the run log says Could not read and names the file. The file stays in the Inbox. Nothing is guessed.
  • Bad run: a silent log, or an output row with made-up values.
  • Fallback: one line in the prompt says what to do, and the named reviewer checks that file by hand.
  • No Drive: if the connector is off, no run log is written. A missing log means: check the run.

Test the failure before Demo Day, not during it.

08Four building blocks. Four jobs.Lesson 1 · Skills · table
  • DoPoint to one column at a time.
  • SayMany people mix up these four words, so let us put them side by side. A prompt is the request you type right now: it is gone when the chat ends. Project instructions are a standing brief, but only for that one Project. A skill is a method Claude keeps on your account and opens when your request fits it, in any chat or schedule. And an agent is not one more button: it is all of these working together to do one job. Look at the last row: a question to a colleague, the planning memo, the audit program, and the trained associate.
09Why we combine them.Lesson 1 · Skills · list
  • SaySo why do we need all of them? Because each one fixes a different gap. The prompt is this run. The Project keeps the client context and the template. The skill keeps the method, so it works anywhere. The input is the file it reads, and the schedule brings the time. Take one away and something breaks: no skill, and your colleagues cannot use it; no input, and there is nothing to check; no schedule, and someone must press Send.
10How Claude picks a skill.Lesson 1 · Skills · term
  • SayHow does Claude know which skill to use? It does not read every skill in full each time. It reads the short description first. If your request fits, it opens the whole skill. So the description is the most important line you write. If it says helps with Excel, Claude will not know when to use it. If it says match supplier invoices to a purchase ledger, it will.

28A calendar reminder that also does the work.Lesson 3 · Scheduled tasks · term

  • SayA scheduled task is a prompt Claude runs by itself on a timetable: every hour, every day, on weekdays, every week, or when you click run. The prompt calls your skill. Today we keep the file inside the skill, so the run needs no connections to other apps. You saw yesterday's run at 16:25: that was one of these.
29Each run starts fresh.Lesson 3 · Scheduled tasks · list
  • SayOne thing to understand. Every run is a brand new session. It does not remember last week, and it does not see your chats. So the prompt names the skill, and the skill holds the file. Today that file sits inside the skill. At work, an approved connection or an automation tool would bring new files each week. Every run starts its answer with one line: when it ran, what it read, what it flagged. And the Scheduled page keeps every run, so you can go back and review.

35Three tools, three strengths.Lesson 4 · Claude, n8n or Power Automate · table
  • DoRead one row at a time.
  • SayThree tools you will hear about. Claude is best at reading, judging and writing: messy documents, summaries, drafts. n8n and Power Automate are best at connecting systems: when this happens in one app, do that in another. Power Automate lives inside Microsoft 365. n8n works with almost any app, and a firm can run it on its own server. And look at the last row: these are usually owned by IT, not by one person.
36What Claude cannot do yet.Lesson 4 · Claude, n8n or Power Automate · list
  • SayTo be fair to Claude, here is what it cannot do today. It cannot start when an email arrives. It is not the right tool to copy thousands of rows exactly, every day. It runs on your own account, without the controls IT expects. It only reaches apps with a connector. And because it is AI, the wording can change from run to run, so you still check. None of this makes it less useful. It tells you where it fits.
37When to switch.Lesson 4 · Claude, n8n or Power Automate · list
  • SaySo when do you move to n8n or Power Automate? When the start is an event. When one flow touches three or more systems. When it runs all day, or the output must be identical. When many people depend on it, so IT must own it. When you need a formal approval with a record. And often the best answer is both: n8n or Power Automate carries the data between systems, and Claude is one step inside the flow that reads and writes.

39Three words for any automation.Lesson 4 · Claude, n8n or Power Automate · table
  • SayBefore the demo, three words you will hear in every automation tool. The trigger is what starts it. Each node, or action, does one small job: read, calculate, decide, call AI. And the output is where the result lands. Between the nodes, the data travels as items. Every run is saved, so you can open it and see what happened.

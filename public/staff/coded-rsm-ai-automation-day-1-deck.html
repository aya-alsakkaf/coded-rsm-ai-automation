Block 1 · Reframing work

Most of the work is not the judgment. It is the moving.

Reading, matching, copying, chasing. An agent can do the first pass.

How an AI model writes

It writes by guessing the next word.

Khiran Logistics' commercial license expires on
31 December 202634%
30 June 202722%
15 March 202717%
the date shown on the license9%
With the file · khiran-kyc-pack.pdf, page 130 September 2026
With a rule · IF UNSURE: write "Not found". Never guess a date.

Without the file, it picks a likely date. With the file, it can read the date. With a rule, it says Not found instead of guessing.

Three steps up

Chat, agent, workflow: three steps up.

01 · Chat

You ask. It answers.

You paste the file and the request every time. Good for one question.

02 · Agent

It knows the job.

A fixed instruction, the rules it follows and a fixed output. You give it the case file.

03 · Workflow

The work starts it.

A form, an email or a new file starts the agent. The result lands where people work.

Today: chat to agent. Tomorrow: agent to workflow.

Audit and onboarding

Where the hours go in audit and onboarding.

Audit

  • Vouching invoices to the sales listing
  • Reviewing trial balance movements
  • Matching bank confirmation replies
  • Chasing PBC (prepared by client) items
  • Writing up findings for the management letter

Onboarding

  • Collecting KYC documents
  • Checking expiry dates
  • Finding the beneficial owners
  • Comparing names across documents
  • Filling the client acceptance form

Most of this is reading, matching and copying. That is the part an agent can do first.

The task filter

Four questions find a good candidate.

1

Does it repeat?

Weekly or more. A task you do once a year is not worth building for.

2

Are the rules written down?

A policy, a memo, a checklist. If the rules live in one head, start there.

3

Is the input digital?

A file, a table, an email. Paper first needs scanning.

4

Can a reviewer check it in 2 minutes?

A table or a list, not an essay.

Four yes answers: automate. Two or three: assist. One or none: keep it human.

PAPER OR CLAUDE

Block 2 · Agent Design Framework

An agent is a job description, not a chat.

Input, instruction, output. Get these three right and the tool matters much less.

The framework

Input · Instruction · Output.

Input

What it reads each time.

Name the file, the fields and the format. Example: the KYC pack as one PDF.

Instruction

How it does the job.

Role, steps, rules, what to do when unsure, and the policy it follows.

Output

What a reviewer gets.

A fixed format a person can check in two minutes. Example: a table with named columns.

The agent does the first pass. You sign the file.

Quick check

The agent cannot find a shareholder's ID copy in the pack. What should a good instruction make it do?

A guess looks exactly like a fact. Not found is something a reviewer can act on.

Test before you trust

Three test cases, written before you run them.

Normal

Everything is there.

Does the agent say so, without inventing problems?

Missing data

One item is not there.

Does it write Not found, or does it fill the gap?

Trap

It looks fine but breaks a rule.

A date inside the 60-day window, two names that almost match. Does it catch it?

Write the expected answer first. Otherwise you will believe the output.

CLAUDE

Block 5 · Test and improve

When the answer is wrong, fix the instruction, not the answer.

If you fix the answer by hand, the agent makes the same mistake on the next case.

Read the output like a reviewer

Four checks on every output.

  • Every number and date traces to a file and a page.
  • Every Not found is really not in the file.
  • Nothing is added that the file does not say.
  • The format matches your card, in the same order.

If one check fails, change one line of the instruction and run all three tests again.
